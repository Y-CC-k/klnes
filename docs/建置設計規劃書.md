## 1. 專案目標

提供一個**免安裝、免登入**的線上國字筆順練習網站，讓國小學生可以：

1. 看筆順動畫，建立正確筆順概念。
2. 跟著描寫，即時獲得正確／錯誤回饋。
3. 挑戰無提示測驗，驗收學習成果。
4. 查詢字義（注音、拼音、部首、總筆畫、釋義、例句）。
5. 以姓名累積成績，產生班級排行榜，形成練習動機。

### 設計原則

- **零門檻**：開啟網頁即可用，不需帳號、不需安裝。
- **資料可信**：筆順字形採用開源 `hanzi-writer-data`，字義採用萌典（教育部辭典資料）。
- **快速回饋**：書寫判定即時、動畫流暢。
- **版面完整利用**：單頁三欄式儀表板，填滿視窗、不需大幅捲動。

## 3. 功能需求

### 3.1 選字

- 三組內建字表（低年級常見字／中年級生活字／筆畫多挑戰字）。
- 「練這個字」自由輸入：支援直接輸入單字或詞語（自動取最後一個國字）。
- 字表以按鈕格子呈現，目前選取字以藍底標示。

### 3.2 三種練習模式

| 模式 | 識別 | 行為 |
| --- | --- | --- |
| 筆順動畫 | `animate` | 循環播放筆順，不判定書寫 |
| 引導練習 | `guided` | 顯示輪廓，照筆順描寫；寫錯會提示 |
| 挑戰測驗 | `free` | 不給提示，完成後記錄正確／錯誤次數 |

- 任一模式皆可「▶ 播放一次動畫」。
- 顯示即時統計：✅ 正確筆數、❌ 錯誤次數。

### 3.3 基本資訊（右上）

- 注音（萌典）
- 拼音（萌典）
- 部首（萌典 `radical`，查無資料時退回內建部首對照表）
- 總筆畫（萌典 `stroke_count`，查無資料時退回字形資料筆畫數）

### 3.4 萌典查詢（右下）

- 顯示前 2 個讀音（heteronym），每個讀音最多 3 條釋義。
- 每條釋義顯示：詞性標籤、釋義、1 個例句。
- 提供萌典字圖連結（`/uni/{字}.svg`）。

### 3.5 成績與排行榜（中下）

- 完成測驗（引導／挑戰）後寫入 Supabase。
- 排行榜以「姓名」彙總：總正確筆數排序，取前 10 名，顯示練習次數。
- 名字儲存在 `localStorage`，下次自動帶入；未填名字記為「匿名」。

## 5. 資料設計

### 5.1 資料表 `stroke_results`

```sql
create table if not exists public.stroke_results (
  id         uuid primary key default gen_random_uuid(),
  created_at timestamptz not null default now(),
  name       text not null,          -- 練習者姓名（未填為「匿名」）
  char       text not null,          -- 練習的字
  mode       text not null,          -- animate / guided / free
  total      int  not null default 0,-- 該字總筆畫
  correct    int  not null default 0,-- 正確筆畫數
  ms         int                     -- 花費毫秒
);
```

### 5.2 存取政策（RLS）

- 已啟用 Row Level Security。
- 允許 `anon` 角色 `insert`（寫成績）與 `select`（讀排行榜）。
- 前端僅使用 **publishable（公開）金鑰**，不得放入 service role 金鑰。

### 5.3 排行榜計算方式

1. 取最近 1000 筆（`order by created_at desc`）。
2. 以 `name` 分組：`correct` 加總、`count` 計次。
3. 依總正確筆數降冪排序，取前 10 名。

> 目前為前端彙總；資料量成長後建議改為資料庫 view 或 RPC（見 §11）。

### 6.2 狀態管理

單一 `App` 元件集中管理狀態，未引入外部狀態庫：

| 狀態 | 用途 |
| --- | --- |
| `name` | 練習者姓名（同步 `localStorage`） |
| `setNameIdx` | 目前字表索引 |
| `char` | 目前練習字 |
| `mode` | 練習模式 |
| `runId` | 重開一輪測驗（遞增觸發重繪） |
| `custom` | 自訂字輸入 |
| `dict` / `dictLoading` | 萌典資料與載入狀態 |
| `strokeCount` | 字形資料筆畫數（備援） |
| `leaders` | 排行榜資料 |
| `savedMsg` | 完成提示訊息 |

`StrokePractice` 以 `key={char-mode}` 強制重建，並以 `runId` 重啟測驗，確保切換字／模式時畫布狀態乾淨。

### 6.3 畫布（StrokePractice）

- `HanziWriter.create(host, char, {...})`，尺寸隨視窗自動計算（260–680px，20px 級距）。
- 視窗 resize 時重新計算；變動小於 40px 不重建，避免練習進度被重置。
- 筆畫樣式：主要筆畫 `#1f2937`、部首 `#15803d`、輪廓 `#cbd5e1`、書寫 `#2563eb`。
- 線寬：`strokeWidth 5`、`outlineWidth 3`、`drawingWidth 6`（加粗以利投影與觸控）。
- 動畫節奏：`delayBetweenStrokes 220ms`。
- 事件：`onMistake` / `onCorrectStroke` 更新統計；`onComplete` 觸發成績上傳。

### 6.4 字形資料載入器

```
jsdelivr（主）→ unpkg（備援）→ 顯示「無法載入字形資料」
```

自訂 `charDataLoader` 實作循序 fallback，避免單一 CDN 故障造成無法練習。

## 8. 資料流

### 8.1 換字

```
使用者點字／輸入字
  → App.setChar + setRunId+1
  → StrokePractice 重建 → charDataLoader 抓字形 → 依模式播放動畫或開始描寫
  → App 併發查詢萌典（/uni/{字}.json）與筆畫數 → 更新基本資訊與字典區
```

### 8.2 完成一輪測驗

```
onComplete（限 guided / free）
  → onSessionComplete({char, mode, strokesTotal, correct, mistakes, ms})
  → saveResult() 寫入 Supabase
  → setSavedMsg 顯示成果
  → loadLeaderboard() 重新整理排行榜
```

## 9. 可靠度與效能

| 議題 | 對策 |
| --- | --- |
| 字形 CDN 故障 | jsDelivr → unpkg 自動備援，失敗顯示提示 |
| 字典 API 失敗 | `lookupMoedict()` 回傳 `null`，顯示「查不到資料」，不影響練習 |
| 部首／筆畫缺資料 | 依序退回內建部首表、字形資料筆畫數 |
| Supabase 失敗 | `console.warn` 記錄，不阻斷 UI |
| 重複請求 | 以 `alive` 旗標避免換字競態（只採最后一次結果） |
| 大螢幕留白 | 畫布依可用寬高自動放大（上限 680px） |
| 動畫太重 | 僅目前字載入字形 JSON，無預載全部字庫 |

## 10. 建置與部署

### 10.1 部署流程

```
git push origin main
  → GitHub Actions：checkout → setup-node 20 → npm ci → npm run build
  → upload-pages-artifact（dist）
  → deploy-pages（GitHub Pages）
  → https://Y-CC-k.github.io/klnes/
```

### 10.2 關鍵設定

- `vite.config.ts`：`base = command === "build" ? "/klnes/" : "/"`（正式站在子路徑、本機開發用根路徑）。
- Repo → Settings → Pages → Source 需設為 **GitHub Actions**。
- 環境變數於 workflow 注入：`VITE_SUPABASE_URL`、`VITE_SUPABASE_ANON_KEY`。

### 10.3 本機開發

```powershell
cd D:\A\stroke-practice
npm install
Copy-Item .env.example .env    # 填入 Supabase URL / publishable key
npm run dev                    # http://localhost:5179
npm run build                  # 型別檢查 + 打包至 dist/
npm run preview                # 預覽打包結果
```

> 注意：`npm run build` 會產生 `tsconfig.tsbuildinfo`（建置產物），提交前請勿加入版控。

## 11. 後續規劃

| 優先序 | 項目 | 說明 |
| --- | --- | --- |
| 高 | 排行榜改用 DB view / RPC | 目前前端彙總 1000 筆，資料量增大會變慢 |
| 高 | 成績防寫入濫用 | 加入 rate limit 或 Edge Function 驗證 |
| 中 | 進度記錄與複習清單 | 記錄每人常錯字，提供「再練一次」 |
| 中 | 字表擴充 | 依年級／課次建立字表，支援教師自訂字表 |
| 中 | 離線可用 | Service Worker + 字形快取 |
| 低 | 多語系（臺語／客語） | 萌典另有臺語、客語資料 |
| 低 | 教師儀表板 | 班級成績彙總、錯誤熱點分析 |

### 風險與限制

- 萌典為外部免費服務，回應速度與可用性不受控（已做錯誤處理）。
- 公開資料庫金鑰僅能防君子，RLS 無法阻止惡意大量寫入。
- hanzi-writer 僅支援標準字型筆順，異體字可能無字形資料。
